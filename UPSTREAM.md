# Upstream discussions and deliberately separate findings

**Already reported:** [Metal2Vulkan #17](https://github.com/steelbrain/metal2vulkan/issues/17) (Clear-loaded attachment self-read and stale Spotlight pixels), with the [historical diagnostic source patch](patches/EXPERIMENTAL-spotlight-clear-selfread.patch), [exact replay hashes](manifest/spotlight-selfread-source.json), and bounded [on/off visual observations](diary/spotlight-clear-selfread.md). That diagnostic patch is not directly applicable to current upstream master, and a permanent environment toggle is not proposed.

**November 17 current-source follow-up, not yet posted upstream:** [Same-binary native self-read ON/OFF, ported 053e789a diagnostic source, and paired historical/current QEMU screenshot evidence](evidence/spotlight-2026-11-17/README.md). The *native* Clear-loaded self-read discrepancy still reproduces; actual current Spotlight UI captured with Control+Space was visually clean in both modes, unlike our October 29 historic controls. Do not claim the visible GUI bug currently persists without a new genuine reproduction.

**Relevant ongoing discussion:** [Metal2Vulkan #11](https://github.com/steelbrain/metal2vulkan/issues/11) reports substantial shadow/copy cost on RADV. We have different NVIDIA data: [selective byte stores](diary/selective-byte-store-regression.md) passed narrow source tests but regressed from ~30 to ~6.47 presentations/s, and [direct external-memory image rendering](archive/direct-external-import-negative.md) likewise regressed. These are independent cautionary results, not proof of the same cause or a proposed vendor-specific fix.

**Later actual guest results (16 November 2026):** We completed the requested [real animated 1080p Sequoia forest A/B](benchmarks/2026-11-16-sequoia-screensaver-ab/README.md) with both the accepted REIMS integration and current Metal2Vulkan master d9236a8 producing correct changing QEMU frames at approximately 30 guest presentations/s. Across **three valid 60-second runs each**, GPU busy averaged **20.028% accepted versus 20.433% current master**. The reported 76.7%→~19.8% historical result is *not* a master comparison. Two REIMS-side device-identity cache fixes were necessary to make the current master integration render correctly; Metal2Vulkan source itself remained pinned and unchanged. See the raw per-second data, full-frame hashes, quality gates and rejected cold-start/transition cases in the evidence archive. No upstream response has been posted as part of this completed A/B.

**Maintainer-requested comparison (16 November 2026):** In response to the follow-up on [#11](https://github.com/steelbrain/metal2vulkan/issues/11), we measured the same standalone 1080p pitched private-IOSurface workload against upstream d9236a8 and our locally integrated October snapshot on the same physical RTX 2080 Ti used by the guest. See [benchmark source and 8 alternating run results](benchmarks/2026-11-16-master-vs-accepted/README.md). The old integration averaged 20–23% lower per-frame completion latency, but current master already classifies private IOSurface backing explicitly. At that point we had not isolated a current-master PR-sized change or measured current master in a full macOS VM; the later full-guest report above now supplies that separate evidence. A single-branch ablation was prepared but not completed because guest GPU load became active. **No reply to #11 has been posted yet.**

**Related REIMS work:** [REIMS #157](https://github.com/steelbrain/reims-vgpu/issues/157) describes expensive synthetic registration of scattered video buffers, while [REIMS #107](https://github.com/steelbrain/reims-vgpu/pull/107) and [#108](https://github.com/steelbrain/reims-vgpu/pull/108) concern reuse/merge and copy paths. Avoid conflating these separate source contracts.

The [private internal-backing case](archive/private-backed-surfaces.md) has an independently checked small classification patch but not an end-to-end current-master hardware validation. Any future upstream issue or PR would need a scoped reproduction on the present architecture.

No new upstream issues, PRs or comments were posted while curating this expanded source archive.
