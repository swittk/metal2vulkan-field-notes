# Diary — selective byte-store optimization REJECTED (October 30, 2026)

A proposed shadow merge wrote only changed bytes instead of reading/modifying whole destination words. Narrow correctness/interpreter and SPIR-V checks passed; generated byte-store path avoided destination buffer loads. It did **not** become the production implementation.

## Actual live A/B/A

Same 1920x1080 guest animation, successive 30-second trials on one anonymized GPU host:

| Run | GPU busy | Presentation callbacks/sec | Board power |
|---|---:|---:|---:|
| Original implementation | **61.97%** | **30.07** | 108.46 W |
| Selective byte-store candidate | **97.60%** | **6.47** | 123.31 W |
| Original implementation restored | **62.23%** | **30.00** | 103.57 W |

The execution queue's median GPU-until-complete was around **40 ms** for the candidate versus **4.35 ms** for the control, while the display readback queue stayed around 0.25 ms.

This localizes the severe regression to the GPU execution path, **without proving a specific hardware-level cause**. Reduced loads were outweighed by other factors, and no portable optimization claim was earned. Some measurements differ in thermal/power state, so do not promote a power savings claim.

The historical patch is intentionally named [REJECTED-selective-byte-stores.patch](../patches/REJECTED-selective-byte-stores.patch) and is **not recommended for application**. Its original source base is experimental; current upstream applicability has not been validated.

See [metal2vulkan #11](https://github.com/steelbrain/metal2vulkan/issues/11) for a related but separately measured RADV shadowing regression.
